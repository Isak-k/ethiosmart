# ExamPro: Educator Guide — Creating Mixed-Type Exams

This guide is for teachers, educators, and exam administrators who want to create
exams that contain **MCQ, True/False, Short Answer, and Essay** questions.

**File location:** `src/components/admin/QuestionTypeForm.tsx`
**Edit flow:** `src/pages/CreateExam.tsx` → `src/pages/EditExam.tsx`
**Grading UI for essays:** `src/pages/GradeEssays.tsx` +
`src/components/admin/EssayGradingPanel.tsx`

---

## 1. Overview of Question Types

| Type | Auto-graded | Summary |
|---|---|---|
| **MCQ** (`mcq`) | ✅ Yes | 2–6 labeled options, one correct. Supports shuffle, inline images. |
| **True/False** (`true-false`) | ✅ Yes | Binary answer. Very fast to create and to answer. |
| **Short Answer** (`short-answer`) | ✅ Yes | 1–N accepted answers. Configurable case sensitivity. |
| **Essay** (`essay`) | ❌ Manual grading only | Educator assigns marks via GradeEssays page. Optional min/max words + rubric. |

---

## 2. Step-by-Step Create Exam

1. Open **Dashboard → Create Exam** (or select **Edit** on an existing exam).
2. Fill in the **Exam Metadata**: title, description, duration, department,
   passing percentage, start/end date.
3. Under **Questions** click **+ Add Question**:
   - **Question Type:** use the dropdown to pick MCQ / True/False /
     Short Answer / Essay. The form re-renders with type-specific inputs.
   - **Question text:** plain text (1–2000 chars, validated on save).
   - **Marks:** 1–100 per question.
   - **Image (optional):** JPG/PNG, max 5 MB. Use `imageDisplayMode` to pick
     *inline* (default), *background* or *main* layout.
4. Fill in type-specific fields (see §3).
5. Click **Save Question** — the question row now shows a colored
   **Badge** with the type.
6. Repeat for N questions, then click **Save Exam** at the top of the page.

> 💡 Tip: Mix auto-graded questions for speed and Essays for depth. Exam results
> show the number of **pending essays** so educators know what's left to grade.

## 3. Type-Specific Fields

### 3.1 MCQ (2–6 options)

Required fields:
- **Options**: at least 2, at most 6. Empty options trigger a validation error.
- **Correct option index**: one of the option indices (0-based). The UI renders
  labeled radio buttons.
- **Explanation** (optional): shown in Practice mode after submission.
- **Shuffle**: handled per-exam via `exam.shuffleOptions` (only MCQ choices are
  shuffled; True/False / Short Answer / Essay are **never** shuffled — see
  Phase 7 implementation notes).

### 3.2 True/False

Required fields:
- **Correct answer**: toggle (True / False). Defaults to `true`.
- **Explanation** (optional).

### 3.3 Short Answer

Required fields:
- **Correct Answers**: one or more strings. Any match counts as correct.
- **Case Sensitive?** (default `false`): when `true`, `Nacl` ≠ `NaCl`.
- **Require Exact Match?** (default `true`): toggles fuzzy matching via
  `evaluateTextAnswer` in `src/integrations/firebase/types.ts#L167`.

### 3.4 Essay

Optional fields (all have validation):
- **Min words**: integer ≥ 0, must be ≤ `maxWords` when set.
- **Max words**: integer ≥ 0. If set, responses exceeding it earn 0 auto-marks
  (the essay still moves to **pending manual grading**, with feedback visible to
  educator explaining the breach — see `evaluateEssay` in
  `src/lib/question-evaluation.ts#L134`).
- **Rubric**: list of `{ criteria, points }`. Live total shown while editing.

## 4. Shuffle Settings (Exam-level)

When creating/editing an exam, under **Exam Options**:

| Flag | Behavior |
|---|---|
| `shuffleQuestions` | When `true`, questions are re-ordered randomly at exam start **only for new attempts.** Resuming a previous attempt preserves the saved order. |
| `shuffleOptions` | When `true`, only **MCQ** option buttons are shuffled (the *original* correct index is preserved in storage — display↔original mapping applied at render-time). |

---

## 5. Exam Taking Tips for Educators

- **Timer** (`ExamTimer.tsx`) is type-agnostic — just set `exam.duration`.
- **Auto-save** (debounced 1 s in `TakeExam`) persists answers as the student
  types, including essay text and short answer strings.
- **Keyboard navigation** (← / →) works across all question types since it uses
  a simple index decrement / increment.
- **Practice Mode**: `mode = "practice"` on `<QuestionRenderer>` enables
  instant feedback for auto-graded types; essays still await manual grading.

---

## 6. Essay Grading Workflow

1. After a student submits, go to **Dashboard → Grade Essays**.
2. Select **Exam** and then **Attempt**. All essay answers for that attempt are
   listed.
3. For each essay:
   - Student response + word count shown on the left.
   - On the right panel: enter **marks earned** (≤ `question.marks`) plus
     optional written feedback.
4. Click **Save Grade**. Attempt total marks auto-update via
   `recomputeAndUpdateAttemptScore` in `src/lib/essay-grading.ts`.

The **Exam Results** page will surface `pendingCount` until essays are graded.

## 7. Troubleshooting Validation Errors

| Error | Meaning |
|---|---|
| `Minimum 2 options required` | MCQ has fewer than 2 options. |
| `Maximum 6 options allowed` | Remove extra MCQ options. |
| `Valid correct option index required` | Pick one option as correct. |
| `At least one acceptable answer is required` | Short Answer needs ≥1 string in Correct Answers list. |
| `Marks must be at least 1` / `Marks cannot exceed 100` | Adjust marks. |
| `minWords cannot be greater than maxWords` | Essay constraints conflict. |

If save still fails, open browser DevTools console to see the full validation
summary generated by `formatValidationErrors` in `src/lib/question-validator.ts`.
